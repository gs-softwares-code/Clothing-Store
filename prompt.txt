# PROJECT: Build a Premium UNIQLO-Inspired Fashion E-Commerce Website for GS Softwares

## 1. YOUR ROLE

Act as a principal full-stack engineer, senior e-commerce architect, UI/UX designer, creative director, conversion-rate optimization specialist, and QA engineer.

Your mission is to engineer a premium, production-quality fashion e-commerce website inspired by the user experience, layout philosophy, visual presentation, and shopping experience of:

**Reference website:** https://www.uniqlo.com/in/en/

However, this is NOT an official UNIQLO website, an UNIQLO clone for commercial impersonation, or an attempt to reproduce its proprietary source code.

You are creating an original fictional fashion retail brand as a showcase project for:

**GS Softwares — AI Agent Engineering and Digital Solutions**

The finished website must demonstrate the ability of GS Softwares to design and engineer sophisticated e-commerce platforms for fashion, apparel, lifestyle, and retail businesses.

The result should feel like a real, established international fashion retailer—not a generic template or an agency landing page.

## 4. DESIGN SYSTEM

Build a consistent design system rather than styling each component independently.

### Visual language

Use a refined minimalist fashion-retail aesthetic.

Suggested palette:
- Primary background: White.
- Secondary background: Warm off-white.
- Primary text: Near-black.
- Secondary text: Neutral grey.
- Borders: Very light grey.
- Accent: A restrained, distinctive color for FORME.
- Sale indicators: Clear but visually controlled.

Typography:
- Modern sans-serif.
- Strong editorial headlines.
- Highly readable product information.
- Clear price hierarchy.
- Consistent font weights and spacing.

Suggested typography:
- Inter.
- Manrope.
- Helvetica Neue or an appropriate system alternative.

### Layout principles

- Large edge-to-edge editorial imagery.
- Consistent maximum content widths.
- Responsive product grids.
- Generous vertical spacing.
- Clear visual hierarchy.
- Consistent image ratios.
- Minimal card decoration.
- Smooth but restrained motion.

### Responsive breakpoints

Design deliberately for:
- Mobile: 360px and above.
- Tablet: 768px and above.
- Desktop: 1024px and above.
- Large desktop: 1440px and above.

The mobile experience must be intentionally designed, not merely a compressed desktop layout.

## 8. TECHNICAL ARCHITECTURE

First inspect the existing repository.

Preserve existing working architecture where appropriate. Do not rewrite the project or change frameworks unnecessarily.

If starting from scratch, prefer:

- Next.js with App Router.
- React.
- TypeScript.
- Tailwind CSS.
- Reusable component architecture.
- Neon PostgreSQL.
- Drizzle ORM.
- Zod validation.
- Vercel deployment.

### Suggested architecture

Separate the application into:

1. Presentation layer.
2. Reusable component layer.
3. Domain/business logic layer.
4. API layer.
5. Database layer.
6. Authentication and authorization layer.

Suggested modules:

- products
- categories
- collections
- search
- cart
- wishlist
- checkout
- orders
- customers
- inventory
- promotions
- newsletter

Use server components where appropriate and client components only where interactivity requires them.

Avoid unnecessarily turning the entire application into client-rendered components.

### Database

Use Neon PostgreSQL as the persistent data store.

Suggested tables:

- users
- customer_profiles
- categories
- products
- product_images
- product_variants
- product_inventory
- collections
- collection_products
- carts
- cart_items
- wishlists
- wishlist_items
- addresses
- orders
- order_items
- promotions
- newsletter_subscribers

Use:
- Proper relationships.
- Foreign keys.
- Unique constraints.
- Indexes.
- Database migrations.
- Transactions for order creation.
- Server-side validation.
- Ownership checks.

Do not store the entire application catalogue or order history only in localStorage.

For the demo, seed the database with realistic product data.

If credentials are unavailable, implement a clearly separated demo data adapter while preserving the intended database architecture. Document what requires configuration.

### API

Create versioned, validated API endpoints where appropriate.

Examples:

- GET /api/v1/products
- GET /api/v1/products/[slug]
- GET /api/v1/categories
- GET /api/v1/collections
- GET /api/v1/search
- GET /api/v1/cart
- POST /api/v1/cart/items
- PATCH /api/v1/cart/items/[id]
- DELETE /api/v1/cart/items/[id]
- GET /api/v1/wishlist
- POST /api/v1/wishlist
- POST /api/v1/orders
- GET /api/v1/orders/[id]

Validate input with Zod.

Do not trust client-submitted prices, discounts, inventory, or totals. Recalculate them server-side.
