# Database — FORME

## Status

**Demo mode is the default.** The store runs fully on an in-memory data
adapter: the catalogue is a typed seed module, and orders are kept in a
server-side store for the process lifetime. No configuration is required.

The canonical database design is fully specified and ready:

- **ORM:** Drizzle
- **Database:** Neon PostgreSQL (serverless)
- **Schema:** `db/schema.ts`
- **Migrations:** generated by `drizzle-kit` into `db/migrations/`

## Schema overview

Tables (all in `db/schema.ts`):
`users`, `customer_profiles`, `categories`, `products`, `product_images`,
`product_variants`, `product_inventory`, `collections`, `collection_products`,
`carts`, `cart_items`, `wishlists`, `wishlist_items`, `addresses`, `orders`,
`order_items`, `promotions`, `newsletter_subscribers`.

Design properties:

- Foreign keys + cascade deletes (`product_images`, `cart_items`, `order_items`…)
- Unique constraints (`products.slug`, `product_variants.sku`, `orders.reference`, `newsletter_subscribers.email`)
- Indexes on hot query paths (category+subcategory, collection, order items)
- `order_items` snapshot product name/image/price — orders stay stable even if catalogue changes
- `product_inventory` separates stock from reserved units for transactional availability
- Order creation should be wrapped in a transaction (verify stock → decrement → insert order + items)

## Activating Postgres

1. Create a Neon project (or any Postgres) and copy the connection string.
2. Create `.env.local` (or set on the platform):

   ```
   DATABASE_URL="postgresql://user:password@ep-xxx.region.aws.neon.tech/forme?sslmode=require"
   ```

3. Generate/apply migrations:

   ```bash
   npx drizzle-kit generate   # create SQL migration from schema
   npx drizzle-kit migrate    # apply to the database
   ```

4. Switch the data layer: implement `PostgresDataAdapter` behind the same
   interface used by `lib/server/orders-store.ts` + seed catalogue tables
   from `lib/data/catalog.ts` (a `seed` script is the natural next step).

## Security notes

- Parameterized queries via Drizzle (no string interpolation).
- `DATABASE_URL` is server-only — never import into client components.
- Server-side validation (Zod) for every write; ownership checks on
  carts/wishlists/orders per user when auth is enabled.
- Orders recalculate totals from the catalogue at write time.
